把智能眼镜变成可对话的个人与现场记忆入口

方案核心是让眼镜捕捉一线真实场景，由手机和云端自动判断哪些片段值得保存， 再把音频、关键画面和视频理解结果沉淀为结构化记忆，进入 RAG 数据库， 最终让 AI 在对话中回答“我刚才看到了什么、发生了什么、证据在哪里”。

优先场景 B 端现场记录、巡检、客户拜访、会议复盘，比泛 C 端全天候记忆更容易合规落地。
产品抓手 不是“录很多视频”，而是“只保留有价值证据，并能被 AI 精确召回”。
技术策略 先用成熟国产云 API 跑通闭环，后续再替换成私有化模型和自控向量库。

商业判断

这个机会的价值在于把“第一视角数据”变成“可追溯的行动记忆”。

当前智能眼镜、国产多模态模型、实时语音识别、向量数据库和云存储都已具备可集成基础。 难点从“技术是否存在”转为“是否能选对场景、控制成本、处理隐私、证明用户愿意持续使用”。

1

痛点真实

人会忘记细节，现场工作很难边做边记录，视频资料又难以回看和搜索。

2

数据独特

眼镜获得的是第一视角、低干扰、贴近现场的数据，比手机拍摄更自然。

3

AI 可变现

RAG 把记忆变成可问答的工作资产，适合按席位、设备、存储和行业模板收费。

4

窗口期明确

消费级一体化方案还不成熟，B 端垂直场景有机会先形成产品壁垒。

产品链路

从视频采集到 AI 对话，建议拆成 6 个可独立验证的模块。

早期不要做全天候连续录像。更合理的方式是眼镜和手机维护短时缓存， 由规则与轻量模型判断片段价值，再把值得保存的事件上传到云端做深度理解。

01

眼镜采集

摄像头、麦克风、按键、语音唤醒、场景变化和运动状态。

02

自动判断

手机端做 VAD、人声、关键词、画面变化、用户行为触发。

03

分片上传

把 30 到 120 秒事件片段上传，失败后本地排队重试。

04

多模态理解

ASR、OCR、关键帧描述、视频摘要、人物和地点线索提取。

05

记忆入库

生成结构化事件、向量索引、证据链接、时间戳和置信度。

06

对话召回

用户提问时检索相关记忆，把证据片段交给大模型回答。

推荐选型

先选能最快跑通闭环的组合，再考虑成本优化和私有化。

首版建议采用“国产硬件 + Android 中继 + 国内云 API + 托管知识库”。 这样可以降低硬件和模型研发压力，把前两个月的精力集中在场景验证、数据闭环和演示效果上。

模块 首选方案 备选方案 选择理由
硬件眼镜 Rokid Glass3 Rokid Sprite Enterprise RayNeo、INMO、小米 AI 眼镜 优先看 SDK、摄像头权限、录像/推流能力、供货、商务支持和企业采购路径。Rokid 官方文档覆盖终端 SDK、设备接入、视频流等开发能力。
手机中继 Android App 眼镜直连云、专用边缘盒子 手机负责网络、缓存、压缩、上传和权限提示，能显著降低眼镜端功耗和硬件适配风险。
云基础设施 阿里云 腾讯云、火山引擎、百度智能云、华为云 阿里云百炼、DashScope、OSS、ECS 和知识库链路完整，适合快速 MVP。若重点是实时音视频，可重点评估腾讯云 TRTC。

文本大模型 Qwen DeepSeek 豆包、混元、文心、星火 中文能力、API 可用性、成本和私有化潜力都较重要。可按不同任务拆模型，而不是只选一个模型。

对象存储 OSS COS、TOS、BOS 保存原始视频、音频、关键帧、转写结果和证据截图，必须设计生命周期策略降低存储成本。

系统架构

把复杂系统分层，便于并行开发和替换供应商。

建议用中台化设计隔离硬件、模型和向量库。前期可以全托管，后期逐步把记忆抽取、向量检索、 权限控制和行业知识模板沉淀为自己的核心资产。

核心资产在哪里

真正的壁垒不是眼镜本身，也不是单个大模型，而是“场景触发规则、记忆抽取 schema、 证据引用体验、行业数据集和权限合规流程”。

8 周 MVP 路线

目标是让合作伙伴在真实场景中看到闭环，而不是只看概念演示。

MVP 应控制在一个高频场景内，例如销售拜访、设备巡检、护理交接、门店督导或项目现场记录。 每个场景都要能产出清晰报告，并能在对话中用证据回答问题。

第 1-2 周

场景与硬件验证

  • 选择 1 个垂直场景和 3 个典型任务。
  • 采购或借测 2 到 3 款眼镜。
  • 验证拍摄角度、续航、音频质量、佩戴舒适度。
  • 确认录制提示和用户授权流程。
第 3-4 周

采集与云端处理

  • 完成眼镜到手机的采集链路。
  • 实现分片上传、队列、失败重试。
  • 接入 ASR、关键帧抽取、OCR 和视频摘要。
  • 定义事件记忆数据结构。
第 5-6 周

记忆库与 AI 对话

  • 把事件摘要写入向量库和结构化库。
  • 实现按时间、人物、项目、地点检索。
  • 对话回答必须带来源和时间戳。
  • 产出第一版场景报告模板。
第 7-8 周

试点与商业验证

  • 招募 5 到 10 名真实用户试用。
  • 记录召回准确率、保存成本和使用频次。
  • 访谈付费意愿和采购阻力。
  • 形成 demo、报价和下一轮开发清单。

验证指标

合伙人决策应看可量化结果，而不只看演示是否惊艳。

第一阶段要证明三件事：用户愿意戴，系统记得准，企业愿意为节省时间和降低风险付费。 下面的指标可以作为第一轮验收标准。

产品可用性

  • 从录制到可查询的平均延迟小于 5 分钟。
  • 关键事件召回准确率达到 80% 以上。
  • AI 回答必须提供可回放证据，减少幻觉争议。
  • 单次佩戴 2 小时内不明显影响正常工作。

商业可行性

  • 每名用户每天媒体和模型成本有上限。
  • 目标客户愿意为报告、检索、审计或培训价值付费。
  • 设备采购、云服务和实施成本能被年费覆盖。
  • 隐私流程能被企业法务和管理者接受。
5-10 人 首轮真实用户规模，足够发现佩戴、录音、场景价值问题。
30-120 秒 建议事件片段长度，平衡上下文、成本和隐私风险。
1 个场景 先打透一个刚需场景，不急着做全行业通用记忆助手。

风险与对策

这个项目的主要风险不是 RAG，而是数据采集边界和持续使用。

需要从第一天就把合规、权限、删除、审计和成本做进架构里。否则即使技术 demo 可行， 也很难进入真实客户现场。

风险 影响 应对策略
隐私与旁人同意 可能阻碍商用试点和公共场景使用。 从 B 端授权场景切入，提供明显录制提示、可见权限、脱敏、删除和审计能力。
续航与发热 全天录像不现实，影响佩戴体验。 眼镜只做轻量采集，手机中继和云端处理；使用滚动缓存和事件触发，避免连续上传。
云成本失控 视频、ASR 和多模态模型成本可能吞掉毛利。 先抽音频与关键帧，视频原件设置生命周期；只让高价值片段进入长期记忆。
召回错误或幻觉 用户会失去信任，尤其在工作证据场景。 所有回答绑定证据片段、时间戳和置信度；不确定时让 AI 明确说明没有足够证据。
硬件供应不稳定 单一硬件路线可能导致项目停摆。 设备层做适配器，把采集接口标准化；并行评估至少 2 个硬件供应商。

行动方案

行动重点围绕三件事：关键点选择、技术方案设计、Demo 成本估算。

合作伙伴第一次会议要避免泛泛聊市场，建议直接产出三份决策结果： 选哪个场景、用哪条技术路线、投入多少钱做出可演示 Demo。

A

关键点选择

把场景、硬件、云、模型、隐私边界和试点指标一次性拍板，避免 Demo 做散。

B

技术方案设计

按“眼镜采集、手机中继、云端理解、记忆入库、AI 对话”拆模块设计。

C

Demo 成本估算

先算 8 周 Demo 的硬件、云服务、模型调用、开发人力和试点成本。

D

试点决策

Demo 成功后再决定行业 PoC、私有化部署、硬件定制和融资/商务推进。

1. 关键点选择清单

关键点 建议选择 需要验证
首个场景 B 端现场记录 优先选设备巡检、销售拜访、门店督导、护理交接之一。 是否有明确付费方；是否能减少记录时间；是否允许佩戴和录制；是否需要证据追溯。
硬件路线 Rokid 优先 同时保留 RayNeo / INMO / 小米作为备选。 SDK 是否开放摄像头、录音、录像、推流；是否能稳定连接手机；是否能采购 2-3 台测试机。
采集策略 事件触发 不做全天候连续录像，先做 30-120 秒滚动缓存。 哪些触发条件最有效：按键、语音、关键词、人声、场景变化、地理围栏或任务开始/结束。
云与模型 阿里云闭环 OSS + DashScope/百炼 + 知识库，先换速度，不换复杂度。 ASR 准确率、关键帧理解效果、RAG 召回质量、API 成本、数据合规和客户接受度。
隐私边界 必须前置 录制提示、授权说明、保留期、删除权、审计日志。 试点客户的法务和现场管理是否接受；是否需要人脸模糊、敏感词过滤、数据隔离。
Demo 成功标准 可量化验收 从录制到可问答，小于 5 分钟；回答带证据。 召回准确率、转写质量、单位成本、用户佩戴时长、报告节省时间和复用意愿。

2. 技术方案设计

模块 Demo 做法 后续增强
眼镜端 实现拍照/短视频/录音触发；优先拿到媒体文件或短流，不强依赖全天候直播。 增加端侧 VAD、场景变化检测、离线缓存、电量策略和录制状态提示。
手机 App Android 作为中继：设备连接、任务开始/结束、分片上传、失败重试、用户授权页面。 加入本地滚动缓存、弱网队列、加密上传、设备管理和 OTA 适配。
云端 API 后端接收媒体，写入 OSS，异步触发 ASR、关键帧抽取、OCR、视频摘要。 引入任务队列、批处理成本优化、实时状态推送、租户隔离和审计日志。
记忆抽取 LLM 生成事件 JSON：时间、地点、人物、事项、结论、待办、证据链接、置信度。 按行业建立记忆 schema、规则校验、冲突合并、长期记忆压缩和敏感信息脱敏。
RAG 数据库 首版用百炼知识库或托管向量库，索引事件摘要、ASR 文本、OCR 文本和关键帧描述。 迁移到 Milvus/Zilliz、pgvector 或腾讯 VectorDB，做混合检索、重排和权限过滤。
AI 对话 Web Demo 提供时间线、搜索框、对话问答和证据回放，回答必须附来源。 接入企业微信/飞书/CRM/工单系统，自动生成拜访纪要、巡检报告和复盘摘要。

Demo 交付物建议控制为：1 个眼镜采集流程、1 个手机中继 App、1 个云端处理服务、1 个记忆库、1 个 Web 对话台。

3. Demo 成本估算

最小演示版 8-15 万元

适合内部演示：1 款眼镜、1 个场景脚本、手动触发录制、云端处理、RAG 问答和证据链接。

推荐 MVP 18-35 万元

适合找合作客户试点：2-3 台眼镜、Android 中继、自动触发、后台任务、对话台、成本监控和授权流程。

试点增强版 35-80 万元

适合行业 PoC：多用户、多租户、权限隔离、报告模板、稳定性测试、私有化评估和客户现场部署。

成本项 8 周推荐 MVP 估算 估算口径

试点与交付 2-4 万元 试点脚本、客户培训、现场测试、隐私材料、演示视频、复盘报告和问题修复。

成本锚点来自公开价格页和常见外包/内部人力口径：小米 AI 眼镜等消费级设备价格在数千元级， RayNeo X3 Pro 等高端设备在万元级；阿里云 OSS、ECS、DashScope/百炼、知识库按量计费，实际价格需以采购账号和地区为准。

第 1-2 天：合伙人决策会

拍板首个场景、Demo 预算、角色分工、目标客户名单和 8 周验收指标。
