Text-first Memory Glasses
创业伙伴共享备忘录 · 2026-08-19

从“全天记录”收敛到“文本优先记忆层”

这份备忘录整理本轮方案讨论形成的决策脉络：完整会话音频是主数据源，视觉只在有价值的文本场景中拍静态图，图片延迟批量回传，眼镜端尽量低功耗，手机负责判断，云端负责重处理。

A0/A1/A2 音频状态 L0/L1/L3 视觉策略 LLM 只做触发建议 15-60 分钟批量回传 Rokid 约 6 小时目标

一句话结论

MVP 不做“会看世界的眼镜”，先做“能可靠记住对话和看过文字的个人文本记忆设备”。

关键不是拍得多，而是把音频连续性、文字覆盖率、证据可追溯和续航控制住。

1. 高层结论

产品收敛

从多模态生活记录器，收敛为可检索的个人文本记忆层。音频负责完整会话，视觉负责文字证据。

架构收敛

眼镜只做采集、缓存、批量传输；手机做状态判断和策略控制；云端做 ASR、OCR、索引。

商业收敛

首版价值不靠炫技，而靠真实可用的“我刚才听到什么、屏幕上写了什么、药盒怎么说”。

当前最有把握的 MVP： 完整会话音频 + 人声期间每分钟视觉锚点 + 文本场景短时 1 秒拍照 + 延迟批量回传 + 云端文本化检索。

2. 方案演进

起点：根据商业计划和硬件选型设计软件架构

最初方案覆盖多模态采集、端云处理、记忆索引、隐私和 MVP。这个阶段的问题是范围偏大，视觉策略还容易走向高功耗。

第一次收敛：文本信息比环境影像更重要

用户强调完整会话和完整文字信息，方案转为“文本优先”。音频保存完整会话，视觉只服务屏幕、白板、文档、药盒等文字载体。

关键澄清：完全关闭相机时无法知道画面变化

“白板、屏幕、药盒变化时立即拍照”不能在相机完全关闭时实现。必须依赖低频探测、会话语义、用户触发或短时预览。为了续航，最终选择低频静态拍照和语义触发。

第二次收敛：延迟回传换续航

Rokid 方案中，每张图片即时 P2P 会消耗大量无线建连和尾能耗。缓存 15-60 分钟再批量回传，可以显著降低无线唤醒次数。

最终策略：A0/A1/A2 + L0/L1/L3

音频用三态保证隐私和会话完整性；视觉用三档控制功耗和信息价值。LLM 可以参与判断文本场景，但只能给建议，不能直接控制相机。

3. 核心采集策略

核心策略来自架构文档中的高亮部分，是目前最值得对齐的产品和工程边界。

音频状态

状态 进入条件 采集行为 退出条件
A0 private 用户暂停、敏感地点或隐私日程 不保存原始音频，不触发视觉 用户显式恢复
A1 listening 默认佩戴状态 低功耗 VAD，维护 60-120 秒加密预录环 检测到持续人声进入 A2
A2 conversation 人声持续 3-5 秒、多说话人、日程命中或手动开始 连续录音，按 60 秒切片，保留静音和重叠说话 会话结束判定成立

视觉等级

等级 相机策略 激发条件 回传策略 退出和限流
L0 off 相机关闭 默认非会话、隐私暂停、低电或过热 无 检测到人声、用户手动记录或强日程命中后进入 L1
L1 voice-scout 每 1 分钟拍 1 张低/中分辨率静态图 持续人声 3-5 秒，或 A2 会话已开始 15-60 分钟批量 P2P 回传 无人声、用户暂停、低电降级或连续无文字后回 L0
L3 scene-burst 每 1 秒拍 1 张静态图，单次 10-30 秒 手机端根据会话内容判断为屏幕、白板、文档、药盒等文本场景 先传 manifest 和关键帧，再传完整图片序列 场景结束、指纹稳定、限流、温度或电量降级后回 L1
重要边界： L3 是短时高频静态拍照，不是视频。L1 是保底视觉锚点，不承诺单靠每分钟一张图还原所有文字。

4. 最简软硬件架构

眼镜端

麦克风、静态相机、本地缓存、BLE 控制、P2P 批量传输、电量/温度遥测、录音/拍照提示。

手机端

后台采集服务、VAD、低延迟转写、LLM 触发、策略门控、P2P 接收、加密缓存、上传队列。

云端

Ingestion、完整 ASR、OCR/版面恢复、去重拼接、证据定位、全文检索和 RAG 问答。

模块 位置 最小职责 扩展方式
GlassDeviceAdapter 眼镜 封装麦克风、拍照、BLE、P2P、文件、电量和温度 更换 Rokid、Mentra 或自研硬件时只替换 adapter
AudioSessionManager 手机 管理 A0/A1/A2，固化预录，生成会话 ID 可接入更强 VAD、说话人检测和日程上下文
VisualLevelScheduler 手机 管理 L0/L1/L3，计算拍照间隔和 burst 时长 未来可增加手动 L2 或场景专用策略
VisualTriggerProvider 手机/云端 根据短转写判断是否值得进入 L3 规则、云端 LLM、本地 LLM 都输出同一 schema
CapturePolicyGate 手机 用隐私、电量、温度、冷却和配额审核 L3 通过远程配置调阈值，不改主状态机

5. LLM 触发架构

LLM 适合处理“这一页、右边表格、药盒说明、白板这里写的是”这类语义触发，但不适合直接控制相机。推荐架构是：LLM 做判别器，策略门控做最终执行。 

眼镜麦克风
  -> 手机端低延迟 ASR / 关键词
  -> VisualTriggerLLM 输出结构化建议
  -> CapturePolicyGate 检查隐私、功耗、温度、配额
  -> VisualLevelScheduler 切换 L1/L3
  -> GlassDeviceAdapter.takePhoto()
  -> 本地缓存 + 延迟回传

LLM 输入窗口

只看最近 10-20 秒粗转写、会话状态、最近 L1 图片粗分类、日程、电量、温度和隐私状态。

LLM 输出

只输出 should_trigger_l3、scene_type、confidence、ttl_seconds、reason_code。

allow_l3 = LLM 建议触发
  and confidence >= 0.75
  and audio_state == A2
  and privacy_allows
  and battery >= 20%
  and thermal == normal
  and l3_budget_left > 0
  and cooldown_expired

6. Rokid 可行性判断

开发者文档层面，Rokid 支持这套“缓存后批量回传”的关键能力：眼镜端拍照并写文件，眼镜端发送文件，手机端建立 P2P 并接收文件。因此方案可落地，但需要我们自己实现 manifest、批处理、ACK 和清理逻辑。

能力 文档判断 架构含义
拍照落本地文件 支持 takePhoto(photoResolution, path) L1/L3 图片可以先缓存，不需要即时传手机
眼镜发文件给手机 支持文件发送、进度、完成和停止 可以按 manifest 多次发送图片和音频分片
手机端 P2P 支持请求连接 P2P、断开和文件接收 可以做 15-60 分钟批量回传，完成后断开
官方未提供 没有看到目录级批量拉取和功耗保证 批量协议和真实节电幅度必须自研并实测

7. 续航估算

续航估算按开发预算，不是厂商承诺。核心假设是 Rokid 电池 210mAh，85% 可用容量约 178.5mAh；图片延迟批量回传，避免每张图单独唤醒 P2P。

A1 + L0

约 6.9-9.9h

Rokid 低功耗监听，无相机。

A2 + L1

约 4.3-6.0h

完整会话音频 + 每分钟 1 张图。

A2 + L3

约 1.9-2.7h

完整会话音频 + 每秒 1 张图，只能短时运行。

6 小时佩戴组合 构成 Rokid 估算 结论
轻会话日 4.5h A1 + 1.3h A2/L1 + 0.2h A2/L3 约 6.6 小时 可以覆盖半天级轻量使用
合理混合目标 4.0h A1 + 1.5h A2/L1 + 0.5h A2/L3 约 5.9 小时 接近 6 小时，需要严格批量回传和 L3 限流
文字密集会议 3.0h A1 + 2.0h A2/L1 + 1.0h A2/L3 约 4.9 小时 L3 累计 1 小时后很难维持 6 小时
推荐产品参数： Rokid 路线中，L1 可以作为人声期间默认视觉保底；L3 在 6 小时佩戴内累计控制在 20-30 分钟。标准批量回传 15 分钟，省电模式 60 分钟。

8. MVP 路线

阶段 目标 验收
M0 硬件打通 眼镜拍照、录音、缓存、P2P 文件传输 手机能收到带 manifest 的音频和图片
M1 A1/A2 VAD、预录、完整会话、60 秒音频切片 会话开头丢失不超过 2 秒
M2 L1 A2 期间每 1 分钟拍照，15 分钟批量回传 图片序号连续，ACK 后眼镜可清理
M3 L3 规则版 基于关键词进入 1 秒拍照 burst 文本场景触发延迟不超过 2 秒
M4 L3 LLM 版 LLM 输出结构化决策，策略门控批准 误触发率、漏触发率和功耗可量化
M5 云端文本化 ASR/OCR 入库，证据可回溯 文本可检索，能定位到音频时间和图片

9. 风险与待验证

功耗真实性

Rokid 文档没有公开 P2P 建连和拍照的电流曲线，续航数字必须用真机 60 分钟分项压测校准。

后台稳定性

Android 锁屏、App 退后台、系统回收、弱网恢复都可能影响完整会话和批量传输。

LLM 误触发

误触发会耗电和侵犯隐私，漏触发会丢文本。必须有规则兜底、置信度阈值和配额限流。

文字完整性

每分钟 L1 只能保底，不能保证滚动屏幕、翻页文档和药盒转面完整，需要 L3 和用户辅助。

下一个真机验证： 测四组 60 分钟工况：A1/L0、A2/L1 本地缓存、A2/L1 即时 P2P、A2/L1 15/60 分钟批量 P2P。记录 mAh、温度、文件丢失、P2P 次数和传输耗时。
